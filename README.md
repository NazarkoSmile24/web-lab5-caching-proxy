# Лабораторна робота №5 — Кешуючий проксі-сервер

Автор: Назар Цепух, група ФЕІ-24.

## Призначення

Сервер отримує JPEG-картинки з http.cat і зберігає їх у файловому
кеші. Повторні запити обслуговуються з кешу без звернення до http.cat.

## Встановлення та запуск

Потрібні Node.js і npm.

```powershell
npm ci
npm start -- --host 127.0.0.1 --port 3000 --cache ./cache
```

Обов'язкові параметри:
- `-h, --host` — адреса сервера;
- `-p, --port` — порт від 1 до 65535;
- `-c, --cache` — тека кешу, яка створюється автоматично.

Довідка: `node main.js --help`.

## HTTP-запити

Шлях має вигляд `/200`: символ `/` і тризначне число від 100 до 999.

| Метод | Дія | Статус |
|---|---|---|
| GET | Отримати картинку з кешу або http.cat | 200 |
| GET | Картинку не знайдено або http.cat недоступний | 404 |
| PUT | Зберегти або замінити картинку в кеші | 201 |
| PUT | Відхилити порожнє тіло запиту | 400 |
| DELETE | Видалити картинку з кешу | 200 |
| DELETE | Картинка відсутня в кеші | 404 |
| Інший метод | Відхилити запит | 405 |

Некоректний шлях повертає 400.
Відповідь 405 містить заголовок `Allow: GET, PUT, DELETE`.

Успішний GET повертає `Content-Type: image/jpeg` і заголовок джерела:
- `X-Cache: HTTP_CAT` — картинку завантажено з http.cat;
- `X-Cache: CACHE` — картинку прочитано з файлового кешу.

## Особливості реалізації

- Використано вбудований модуль `node:http`.
- Зовнішні залежності: `commander` і `superagent`.
- Асинхронні операції виконуються через проміси та async/await.
- Файлові операції використовують `node:fs/promises`.
- PUT приймає байти картинки без перетворення на текст.
- Запис відбувається через тимчасовий файл із подальшим перейменуванням.
- Кеш зберігається між перезапусками сервера та не має строку дії.
- `Cache-Control: no-store` забороняє клієнтське кешування відповіді.
- Для PUT перевіряється непорожнє тіло; коректність JPEG не перевіряється.
- Розмір завантаження не обмежено; тіло PUT читається повністю в пам'ять.

## Перевірка через Postman

Колекція: `Caching_Proxy_Lab.postman_collection.json`.

Змінна колекції:
`baseUrl = http://127.0.0.1:3000`.

Для PUT потрібно вибрати власний JPEG-файл у Body → binary.
Файл має бути доступний у робочій теці Postman.
Файл `own.jpg` не входить до репозиторію.

Перед першим запуском колекції зупиніть сервер через Ctrl+C,
очистьте кеш і знову запустіть сервер:

```powershell
Remove-Item .\cache\* -Force
npm start -- --host 127.0.0.1 --port 3000 --cache ./cache
```

Запускайте всі 8 запитів у заданому порядку, одна ітерація.

Результати перевірки:
- Порожній кеш: 17 успішних тестів, 0 невдалих.
- Перший GET із http.cat: 149 мс; наступний GET із кешу: 4 мс.
- Повторний запуск без очищення: 16 успішних тестів, 1 невдалий.
- Причина: перший запит очікує HTTP_CAT, але отримує CACHE.
  Це очікуваний наслідок збереження кешу.
- Перший GET повторного запуску: 3 мс.

Наведені значення часу стосуються конкретних запусків.

Команди ручного тестування записано у `test.txt`.
